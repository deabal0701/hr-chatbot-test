# MUREUM AI Platform 고도화 로드맵

*Enterprise AI 지식 기반 시스템의 차세대 진화 방향*

NL2SQL + RAG + AI Agent 기반 지능형 업무 자동화 플랫폼

---

## 1. 현재 MUREUM 플랫폼 현황 (As-Is)

### 현재 구현 완료된 핵심 역량

| 기능 | 설명 | 기술 기반 |
|------|------|----------|
| AI Agent | ReAct 패턴 기반 자율적 도구 선택 및 멀티스텝 추론 | LangGraph + ReAct Loop |
| NL2SQL | 자연어 → SQL 변환, 멀티턴 대화 지원 | Intent Rewrite + Few-shot + PII Filter |
| RAG | 사내 문서 벡터 검색 기반 질의응답 | pgvector + Embedding |
| Dashboard | KPI, 추이 차트, 최근 활동 시각화 | Vue 3 + Chart.js |

### 현재의 제약사항

- 단일 질문 → 단일 응답 구조 (복합 분석 불가)
- RAG와 NL2SQL이 독립 파이프라인으로 동작
- 사용자가 질문해야만 동작하는 수동적(Reactive) 방식
- 대시보드는 정적 집계 데이터만 표시

---

## 2. 고도화 비전 개요 (To-Be)

### "묻는 AI"에서 "생각하고 알려주는 AI"로

```
Phase 1: Agentic Analytics        — 질문 하나로 분석 보고서 자동 생성
Phase 2: Cross-Source Knowledge    — 규정 + 데이터를 융합하여 근거 기반 답변
Phase 3: Proactive Intelligence    — 물어보기 전에 이상 징후를 감지하고 선제 알림
```

각 Phase는 기존 MUREUM 아키텍처 위에 점진적으로 확장 가능하며, 독립 또는 조합 적용 가능

## 3. Phase 1 — Agentic Analytics

### 개요

**"질문 하나로, 분석 보고서가 완성됩니다"**

기존 NL2SQL은 하나의 질문에 하나의 SQL을 생성합니다.
Agentic Analytics는 하나의 질문에서 **분석 계획을 수립**하고,
**여러 SQL을 자동으로 체이닝**하여 **종합 인사이트와 시각화**까지 제공합니다.

> *"부서별 실수령액이 낮은 원인을 분석해줘"*
> → 부서별 평균 급여 조회 → 수당/공제 항목 분해 → 전년 대비 비교 → 이상치 탐지 → 원인 분석 보고서 자동 생성

### As-Is vs To-Be 비교

| 구분 | 현재 (As-Is) | 목표 (To-Be) |
|------|-------------|-------------|
| **질의 처리** | 단일 질문 → SQL 1건 생성 → 결과 반환 | 복합 질문 → 분석 계획 수립 → SQL 3~5건 자동 체이닝 |
| **시각화** | 사용자가 차트 유형을 수동 선택 | 데이터 특성(수치/범주/시계열) 분석 후 최적 차트 자동 추천 |
| **인사이트** | 쿼리 결과 테이블만 반환 | 이상치 탐지, 전년 대비 변화율, 추세 해석을 자연어로 제공 |
| **보고서** | 미지원 | 분석 결과를 종합한 요약 보고서 자동 생성 |

### 기술 아키텍처

**Multi-Step SQL Planning Architecture**

```
사용자 질문
    ↓
[Plan Node] 분석 계획 수립 (어떤 데이터를 어떤 순서로 조회할지)
    ↓
[Execute Node] SQL 1차 실행 → 결과 분석
    ↓
[Refine Node] 1차 결과 기반 2차 SQL 자동 생성 (반복)
    ↓
[Synthesize Node] 다중 결과 종합 분석
    ↓
[Visualize Node] 데이터 특성 기반 차트 자동 선택
    ↓
[Report Node] 인사이트 + 차트 + 요약을 보고서로 조합
    ↓
최종 답변 (자연어 해석 + 차트 + 근거 데이터)
```

**핵심 기술 요소**

- **Multi-Step SQL Planner**: LangGraph 조건부 분기를 활용한 SQL 체이닝
- **Auto-Visualization Engine**: 컬럼 타입(수치/범주/시계열) 자동 판별 → 차트 매핑
- **Statistical Insight Generator**: Z-score 기반 이상치 탐지, YoY/MoM 변화율 자동 계산

### 적용 시나리오

**시나리오: HR 부서 — 급여 분석**

사용자 질문:
> *"이번 분기 부서별 인건비가 전분기 대비 어떻게 변했는지 분석해줘"*

Agent 자동 실행 과정:

| Step | 자동 생성 SQL | 분석 내용 |
|------|-------------|----------|
| 1 | 당분기 부서별 인건비 집계 | 현재 현황 파악 |
| 2 | 전분기 부서별 인건비 집계 | 비교 기준 데이터 |
| 3 | 분기 대비 증감률 계산 | 변화율 산출 |
| 4 | 증감률 상위/하위 5개 부서 | 이상치 식별 |
| 5 | 해당 부서 인원 변동 조회 | 원인 분석 |

최종 출력:
- 부서별 인건비 증감 차트 (Stacked Bar)
- 이상치 부서 하이라이트 및 원인 분석
- 요약: *"개발1팀 인건비 23% 증가 — 신규 채용 5명 반영. 경영지원팀 12% 감소 — 퇴사 3명"*

**확산 대상 산업**: 금융(포트폴리오 분석), 제조(생산성 분석), 유통(매출 분석)

## 4. Phase 2 — Cross-Source Knowledge Fusion

### 개요

**"규정과 데이터를 동시에 이해하고, 근거와 함께 답변합니다"**

현재 RAG(문서 검색)와 NL2SQL(데이터 조회)은 별도로 동작합니다.
Knowledge Fusion은 **사내 규정과 실제 데이터를 하나의 답변으로 융합**하여
**근거 추적이 가능한 신뢰할 수 있는 답변**을 제공합니다.

> *"김철수의 남은 연차는 며칠이야?"*
> → 연차 규정 검색(RAG) + 입사일/사용연차 조회(NL2SQL) + 잔여일수 계산(추론)
> → "김철수(2022.03 입사, 4년차)는 연차 16일 중 9일 사용, **7일 남음** [근거: 연차규정 제5조 + employee 테이블]"

### As-Is vs To-Be 비교

| 구분 | 현재 (As-Is) | 목표 (To-Be) |
|------|-------------|-------------|
| **검색 방식** | RAG 또는 NL2SQL 중 택1 | RAG + NL2SQL 결과를 하나의 답변으로 융합 |
| **지식 구조** | 평면적 벡터 유사도 검색 | Knowledge Graph 기반 관계 추론 |
| **답변 품질** | 문서 발췌 또는 쿼리 결과만 제공 | 규정 해석 + 실데이터 적용 + 계산 결과 통합 |
| **근거 추적** | 출처 문서 링크만 제공 | 규정 조항 + DB 데이터 + 추론 경로를 단계별 시각화 |
| **지식 갱신** | 문서 재임베딩 필요 | Graph 관계만 업데이트하면 즉시 반영 |

### 기술 아키텍처

**Hybrid Retrieval + Knowledge Graph Architecture**

```
사용자 질문
    ↓
[Intent Analyzer] 질문 유형 분석 (규정형 / 데이터형 / 융합형)
    ↓ 융합형인 경우
[Parallel Retrieval]
    ├── Vector Search (RAG)      → 관련 규정/문서 검색
    ├── Graph Traversal (KG)     → 엔티티 관계 탐색
    └── SQL Generation (NL2SQL)  → 실데이터 조회
    ↓
[Evidence Fusion] 3개 소스 결과를 LLM이 종합
    ↓
[Answer + Evidence Chain] 답변 + 근거 추적 경로 생성
    ↓
최종 답변 (자연어 답변 + 근거 트리 시각화)
```

**핵심 기술 요소**

- **Hybrid Retrieval**: 벡터 검색(Semantic) + 키워드 검색(BM25) + Graph 탐색 3-way 결합
- **Knowledge Graph**: 사내 규정/제도를 Entity-Relation으로 구조화 (PostgreSQL `ltree` 또는 Neo4j)
- **Evidence Chain**: 답변의 각 구성 요소가 어떤 출처에서 도출되었는지 추적 가능

### 적용 시나리오

**시나리오: HR 부서 — 규정 기반 자격 판단**

사용자 질문:
> *"올해 안식년 대상자는 누구이고, 신청 절차는 어떻게 되나요?"*

| 소스 | 검색 내용 | 결과 |
|------|----------|------|
| RAG (규정) | 안식년 규정 검색 | "근속 7년 이상, 직전 3년 인사평가 B 이상" |
| KG (관계) | 안식년 ↔ 근속년수 ↔ 인사평가 관계 탐색 | 자격 조건 3가지 확인 |
| NL2SQL (데이터) | 근속 7년 이상 + 평가 B 이상 직원 조회 | 대상자 12명 리스트 |

최종 답변:
- 대상자 리스트 (12명, 부서/근속년수/평가등급 포함)
- 신청 절차 안내 (규정 제12조 발췌)
- 근거 트리: `[안식년규정 제3조] → [employee.hire_date] → [evaluation.grade] → 자격 판정`

**확산 대상 산업**

- **법무**: 계약 조항 + 거래 내역 교차 검증
- **의료**: 진료 가이드라인 + 환자 검사 기록 통합 판단
- **컴플라이언스**: 내부 규정 위반 여부 자동 점검

## 5. Phase 3 — Proactive Intelligence

### 개요

**"물어보지 않아도, AI가 먼저 알려드립니다"**

현재 MUREUM은 사용자의 질문이 있어야만 동작하는 **수동형(Reactive)** 시스템입니다.
Proactive Intelligence는 **스케줄 기반으로 핵심 지표를 자동 모니터링**하고,
**이상 징후를 감지하면 원인 분석과 함께 선제적으로 알림**을 전송합니다.

> *매주 월요일 09:00 — Agent 자동 실행*
> → 전주 퇴사율 조회 → 개발팀 퇴사율 300% 급증 감지
> → 퇴직 규정 및 절차 자동 검색 → 원인 분석 보고서 생성
> → HR 담당자에게 Slack 알림: "개발팀 이상 징후 감지 — 즉시 확인 필요"

### As-Is vs To-Be 비교

| 구분 | 현재 (As-Is) | 목표 (To-Be) |
|------|-------------|-------------|
| **실행 트리거** | 사용자 질문 (Reactive) | 스케줄 + 이벤트 기반 (Proactive) |
| **모니터링** | 대시보드 수동 확인 | 핵심 KPI 자동 모니터링 + 이상치 감지 |
| **보고서** | 미지원 | 주간/월간 분석 보고서 자동 생성 (PPT/PDF) |
| **알림** | 미지원 | 이상 징후 감지 시 Slack/Email 자동 알림 |
| **예측** | 과거 데이터 집계만 표시 | 추세 기반 예측 + 시나리오 분석 |
| **대응** | 사람이 직접 분석 후 판단 | AI가 원인 분석 + 권장 조치까지 제안 |

### 기술 아키텍처

**Scheduled Agent + Anomaly Detection Architecture**

```
[Scheduler] Cron 기반 주기적 실행 (일간/주간/월간)
    ↓
[Monitoring Agent] 사전 정의된 핵심 지표 자동 조회
    ├── NL2SQL → 퇴사율, 채용현황, 급여 변동 등
    ├── NL2SQL → 전기 대비 변화율 계산
    └── Statistical Analysis → Z-score, IQR 기반 이상치 탐지
    ↓
[Anomaly Detected?]
    ├── 정상 → 정기 보고서 저장
    └── 이상 감지 →
         ├── [Root Cause Analysis] 원인 추적 SQL 자동 생성
         ├── [RAG Search] 관련 규정/프로세스 검색
         └── [Action Recommendation] 권장 조치 생성
              ↓
         [Alert Engine] Slack/Email/대시보드 알림 전송
              ↓
         [Report Generator] PDF/PPT 보고서 자동 생성
```

**핵심 기술 요소**

- **Scheduled Agent**: Cron + LangGraph 기반 주기적 자율 실행
- **Anomaly Detection**: 시계열 통계 분석 (Z-score, IQR, Moving Average)
- **Auto Report Generator**: NL2SQL 결과 + RAG 컨텍스트 → 구조화된 보고서 자동 생성
- **Multi-Channel Alert**: Slack, Email, 대시보드 푸시 알림

### 적용 시나리오

**시나리오: HR 부서 — 주간 인력 이상 징후 모니터링**

| 시점 | Agent 자동 실행 내용 | 결과 |
|------|---------------------|------|
| 월요일 09:00 | 전주 퇴사/입사 현황 자동 조회 | 퇴사 8명 (평소 대비 267% 증가) |
| 자동 분석 | 부서별 퇴사율 분해 | 개발1팀 5명 집중 퇴사 감지 |
| 원인 추적 | 개발1팀 최근 3개월 초과근무/평가 조회 | 월평균 초과근무 45시간, 평가 하락 추세 |
| 규정 검색 | 퇴직 처리 절차 및 인력 충원 규정 | 긴급 채용 프로세스 안내 |
| 알림 전송 | HR 팀장 Slack 알림 | "개발1팀 이상 징후 — 상세 보고서 첨부" |

자동 생성 보고서 내용:

```
[주간 인력 이상 징후 보고서 — 2026년 3월 3주차]

■ 핵심 발견
  - 개발1팀 퇴사율 전주 대비 267% 급증 (5명 퇴사)

■ 원인 분석
  - 월평균 초과근무 45시간 (전사 평균 18시간의 2.5배)
  - 최근 분기 인사평가 평균 C등급 (전사 평균 B)

■ 권장 조치
  1. 개발1팀 업무량 재분배 긴급 검토
  2. 긴급 채용 프로세스 가동 (규정 제15조)
  3. 잔류 인원 1:1 면담 실시
```

**확산 대상 산업**

- **경영관리**: 주간 경영 지표 자동 보고서, 예산 초과 사전 경고
- **설비운영**: 센서 데이터 이상치 감지, 예방 정비 알림
- **고객관리**: 이탈 징후 고객 자동 감지, 리텐션 캠페인 트리거

## 6. 3단계 고도화 로드맵 종합

| Phase | 사례명 | 핵심 가치 | 기술 키워드 | 확산 산업 |
|-------|--------|----------|------------|----------|
| **1** | Agentic Analytics | 질문 하나로 분석 보고서 자동 생성 | Multi-Step SQL, Auto-Viz, Insight Gen | 금융, 제조, 유통 |
| **2** | Cross-Source Knowledge Fusion | 규정 + 데이터 융합, 근거 기반 답변 | Hybrid RAG, Knowledge Graph, Evidence Chain | 법무, 의료, 컴플라이언스 |
| **3** | Proactive Intelligence | 물어보기 전에 알려주는 AI | Scheduled Agent, Anomaly Detection, Auto Report | 경영관리, HR, 설비운영 |

### 진화 단계

```
현재        →   Phase 1          →   Phase 2              →   Phase 3
묻는 AI        분석하는 AI          융합하는 AI               알려주는 AI
(Reactive)     (Analytical)       (Integrative)           (Proactive)
```

## 7. 기대 효과

### 정량적 효과

| 지표 | 현재 | 고도화 후 | 개선율 |
|------|------|----------|-------|
