# MUREUM - Enterprise AI Knowledge Base Assistant

## 기업의 데이터를 AI로 연결하는 지능형 검색 플랫폼

# Slide 1. 기업이 직면한 문제

## 기업 데이터, 왜 활용하지 못하는가?

### 현실의 문제들

| 문제 | 현상 | 비용 |
|------|------|------|
| **정보 사일로** | 문서는 문서대로, DB는 DB대로 따로 검색 | 직원 1인당 주 5시간 낭비 |
| **전문가 의존** | "이 데이터 좀 뽑아주세요" → SQL 작성 대기 | 의사결정 지연 |
| **반복 질의** | 같은 질문이 다른 채널에서 반복 | 인력 낭비 |
| **맥락 단절** | 앞에서 물어본 내용을 다시 설명해야 함 | 사용자 불편 |

### 기업이 원하는 것

> *"자연어 하나로, 문서와 데이터베이스를 동시에 검색하고,*
> *대화 흐름을 기억하며, 정확한 답변을 즉시 받고 싶다."*

**MUREUM은 이 문제를 해결합니다.**

# Slide 2. MUREUM 소개 — 3가지 AI 엔진, 하나의 플랫폼

## 질문 하나로 문서 검색, DB 조회, 복합 분석까지

### 핵심 AI 엔진

```
┌─────────────────────────────────────────────────────────────────────┐
│                         사용자 질문 입력                              │
│                              ↓                                      │
│                    ┌─── AI Agent ───┐                                │
│                    │  (자동 판단)     │                                │
│              ┌─────┴─────┐    ┌─────┴─────┐                         │
│              ▼           ▼    ▼           ▼                          │
│         ┌────────┐ ┌────────┐ ┌────────┐                            │
│         │  RAG   │ │ NL2SQL │ │  복합   │                            │
│         │ 문서검색│ │ DB조회  │ │  분석   │                            │
│         └───┬────┘ └───┬────┘ └───┬────┘                            │
│             └──────────┴──────────┘                                  │
│                        ↓                                            │
│                   통합 답변 생성                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3가지 검색 모드

| 모드 | 기능 | 예시 질문 |
|------|------|-----------|
| **RAG** (문서 검색) | 사내 문서·정책·규정을 의미 기반으로 검색 | "재택근무 정책이 뭐야?" |
| **NL2SQL** (DB 조회) | 자연어를 SQL로 변환하여 DB에서 데이터 조회 | "2024년 입사자 수는?" |
| **AI Agent** (복합 분석) | 위 두 가지를 자율적으로 조합하여 복합 질문 해결 | "2024년 입사자는 몇 명이고 재택근무 정책은?" |

### AI Agent의 ReAct 추론 과정

```
사용자: "올해 입사자 수와 재택근무 정책을 알려줘"

  🤔 Think  → "입사자 수는 DB 조회, 재택근무는 문서 검색이 필요하다"
  🔧 Action → [SQL Tool] SELECT COUNT(*) FROM employee WHERE ...
  👁 Observe → "입사자 15명 확인"
  🔧 Action → [RAG Tool] "재택근무 정책" 문서 검색
  👁 Observe → "주 2회 재택근무 가능, 사전 승인 필요..."
  ✅ Answer → 두 결과를 통합한 자연어 답변 생성
```

# Slide 3. 핵심 기능 — 기업이 필요로 하는 모든 것

## 엔터프라이즈급 기능을 하나의 플랫폼에

### 1. 대화형 멀티턴 검색

- **세션 기반 대화 기억** — 이전 질문의 맥락을 유지하며 후속 질문에 자연스럽게 응답
- **의도 분석 엔진** — 질문 유형을 자동 분류하고 최적의 검색 전략을 선택
- **모호성 감지** — 불명확한 질문에 대해 구체화 요청

```
사용자: "부서별 직원 수 알려줘"           → NL2SQL 자동 실행
사용자: "그 중 개발팀이 가장 많아?"        → 이전 맥락 유지하여 응답
사용자: "개발팀 재택근무 규정은?"          → 자동으로 RAG 전환
```

### 2. 멀티 LLM · 멀티 DB 지원

| 구분 | 지원 | 특징 |
|------|------|------|
| **LLM** | OpenAI (GPT-4o), Anthropic (Claude) | 실시간 전환, 비용 최적화 |
| **Database** | PostgreSQL, Oracle | 어댑터 패턴으로 확장 가능 |
| **Vector DB** | pgvector | 별도 인프라 불필요 |

### 3. 보안 및 컴플라이언스

- **SQL 인젝션 방지** — 키워드 블랙리스트 + 테이블 화이트리스트 + SELECT 전용 제한
- **PII 필터링** — 개인정보 자동 탐지 및 마스킹
- **감사 추적** — 전체 요청/응답 이력 저장 및 조회
- **읽기 전용 모드** — DB 변경 쿼리 원천 차단

### 4. 관리자 대시보드

- **문서 관리** — CRUD, 벡터 임베딩, 청킹 미리보기
- **설정 관리** — LLM 모델, 파라미터, 보안 설정을 UI에서 실시간 변경 (재시작 불필요)
- **이력 조회** — 사용자별 질의 통계, 상세 내역 확인
- **코드 관리** — 분류 체계, 열거값 관리

# Slide 4. 기술 아키텍처 — 검증된 기술 스택

## 확장 가능하고 안정적인 엔터프라이즈 아키텍처

### 시스템 구성도

```
┌──────────────────────────────────────────────────────────────┐
│                      Frontend (Vue 3)                        │
│              사용자 채팅 UI  |  관리자 대시보드                  │
│                    SSE 실시간 스트리밍                         │
└──────────────┬──────────────────────────────┬────────────────┘
               │ REST API / SSE              │
┌──────────────▼──────────────────────────────▼────────────────┐
│                   Backend (FastAPI)                           │
│  ┌───────────┐  ┌───────────┐  ┌────────────┐               │
│  │ AI Agent  │  │    RAG    │  │   NL2SQL   │               │
│  │ (ReAct)   │  │ (문서검색) │  │ (DB조회)    │               │
│  └─────┬─────┘  └─────┬─────┘  └─────┬──────┘               │
│        └───────────────┼──────────────┘                      │
│                   LangGraph Workflow Engine                   │
│  ┌──────────────────────────────────────────────┐            │
│  │  의도분석 → 컨텍스트검색 → 추론 → 도구실행 → 답변  │            │
│  └──────────────────────────────────────────────┘            │
│         │                │               │                   │
│  ┌──────▼─────┐  ┌──────▼──────┐ ┌──────▼──────┐            │
│  │ Multi-LLM  │  │ Vector Store│ │ SQL Executor│            │
│  │ OpenAI     │  │ pgvector    │ │ PostgreSQL  │            │
│  │ Anthropic  │  │ Embeddings  │ │ Oracle      │            │
│  └────────────┘  └─────────────┘ └─────────────┘            │
└──────────────────────────────────────────────────────────────┘
```

### 기술 스택

| 계층 | 기술 | 선택 이유 |
|------|------|-----------|
| **Frontend** | Vue 3 + Vuex | 반응형 UI, 컴포넌트 기반 설계 |
| **Backend** | FastAPI (Python 3.13) | 고성능 비동기 API, 자동 문서화 |
| **AI Engine** | LangGraph + LangChain v1.0 | 그래프 기반 워크플로우, 상태 관리 |
| **Vector DB** | PostgreSQL + pgvector | 별도 인프라 없이 벡터 검색 |
| **Embedding** | OpenAI text-embedding-3-small | 1536차원, 고품질 임베딩 |
| **배포** | Docker + Nginx | 컨테이너화, 무중단 배포 |

### 차별화 포인트

- **LangGraph 기반 워크플로우** — 단순 체인이 아닌 그래프 기반으로 조건 분기, 반복, 재시도 가능
- **SSE 실시간 스트리밍** — 단계별 처리 과정을 실시간으로 사용자에게 전달
- **동적 설정 시스템** — DB 기반 설정으로 서버 재시작 없이 실시간 반영
- **어댑터 패턴** — 새로운 DB 추가 시 어댑터만 구현하면 즉시 연동

### 왜 MUREUM인가?

> **MUREUM**은 단순한 챗봇이 아닙니다.
>
> 기업의 **문서**와 **데이터베이스**를 하나의 자연어 인터페이스로 통합하고,
> **AI Agent**가 복잡한 질문도 자율적으로 분석하여 답변하는
> **엔터프라이즈 AI 지식 플랫폼**입니다.
>
> 검증된 기술 스택 위에 구축된 MUREUM으로,
> 기업의 데이터 활용 역량을 한 단계 끌어올리세요.
